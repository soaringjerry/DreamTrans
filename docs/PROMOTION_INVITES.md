# 推广邀请

超级管理员在 `/pro/admin` →「推广邀请」创建活动渠道码，复制
`/pro?invite=CODE` 链接。可配置活动名、渠道、来源标签、注册截止时间、人数上限、
额外赠送余额（USD）及有效天数、赠送套餐及有效天数。也可只记录渠道，不赠送权益。
邀请码可自定义（6–48 位字母、数字、下划线、连字符，不区分大小写）或随机生成。

注册页使用「昵称」，邀请码输入默认折叠；邀请链接自动进入注册页并填码，展示
活动权益。用户可以展开修改。预览不保证占位，最终以提交注册时的事务校验为准。

## 发放与归因

- 每个新账号只能绑定一个注册邀请。来源标签、渠道和奖励配置创建后不可修改；
  需要调整时暂停旧邀请并新建，避免历史渠道或已承诺权益变化。
- 成功创建账号即占用一个名额，包括待验证账号。创建账号失败不占位。暂停、
  到期和人数限制只影响新注册；已接受的邀请在邮箱验证后仍可兑现。
- 余额是额外的 `promo` 赠送余额，与系统试用余额叠加。有效期从领取时计算，
  账本和账户页显示活动名、原始金额、余额和到期时间；优先消费较早到期的赠送额度。
- 套餐是独立的限时权益，没有消费额度，不创建 Stripe 订阅、不自动续费。
  已有有效付费/手动指定套餐优先；否则使用仍在有效期内的赠送套餐，到期回到免费版。
  套餐定义本身仍遵循现有系统语义：管理员修改套餐功能/折扣时，所有使用者一起更新。
- 邮箱验证并通过注册风控后发放（见 `SIGNUP_RISK.md`），账本写入、套餐权益与领取记录在一个事务中提交。失败后重新登录
  会重试，重复验证或并发登录不会重复发放。用户禁用时不发放。
- 管理页显示注册、验证、领取人数及分页明细。用户列表显示活动、渠道和来源标签，
  支持搜索。这些是服务端注册归因，不将链接预览请求当作真实访客。
- 删除账号后保留去标识的领取记录、名额和规范化邮箱摘要以防重复领取，不保留
  该记录中的昵称或明文邮箱。原邮箱摘要仍属于需要按部署方保留策略管理的数据。

## 注册配置兼容

`REGISTRATION_ENABLED=false` 仍关闭所有自助注册，推广码不能绕过。
推广注册要求启用邮箱验证（默认开启）并配置邮件投递。
`REGISTRATION_INVITE_CODE` 继续支持旧的全局准入码，使用它不会领取推广权益。
配置了全局码时，有效推广码也可作为注册邀请；两个码不能同名。
普通开放注册不需要邀请码。邀请码不是登录令牌，不授权加入其他租户、课程或管理员角色。

## 部署与接口

运行新后端前执行 `036_promotion_invites.sql`。迁移运行器和启动检查均已更新；
Compose 与安装器沿用原有迁移流程。

- `GET /api/auth/invite?code=...`：公开预览活动名与权益，隐藏渠道、标签及用户数据。
- `GET /api/admin/promotions?page=1&search=...`：分页搜索活动、渠道、码或标签。
- `POST /api/admin/promotions`：创建邀请。
- `PATCH /api/admin/promotions/{id}`：`{"enabled": false}` 暂停，`true` 恢复。
- `GET /api/admin/promotions/{id}?page=1`：分页查看注册和领取记录。

管理接口仅超级管理员可用，沿用 JWT 鉴权；公开预览与注册沿用限流。
推广码为可反复复制的渠道标识，管理员列表可读取完整码。分享链接使用当前管理站点
的 origin，因此应在用户实际访问的公网域名打开管理后台后复制。
