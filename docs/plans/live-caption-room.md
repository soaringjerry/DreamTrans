# Plan: 共享实时字幕房（Live Caption Room）

**状态**: 待办 / 未立项  
**优先级**: P1（半刚需 — 场景刚需，非全产品刚需）  
**产品定调**: 一台主机采音+转录，多端只读字幕；不是多人协作会议  
**最后更新**: 2026-08-02

---

## 1. 为什么要记一笔

- **个人用户**: nice-to-have，单人转录已闭环。
- **同一物理空间、多人要看同一份字**（课堂 / 会场 / 展会 / 多语观众）: 场景刚需。
- **成本叙事**: 贵的是 Speechmatics 实时流（约 $0.24–0.43/小时/路）。N 人各自开录 = N 路 ASR；1 主机 + N 观众 = 1 路 ASR + 廉价 fan-out。
- **结论**: 不刚需到必须现在排期，但刚需到不能从产品想象里删掉。放在路线图二线，等信号再上。

---

## 2. 立项触发条件（任一出现即可启动 MVP）

- [ ] 连续有用户/售前问「能不能一起看 / 分享链接 / 扫码看字幕」
- [ ] 有明确的课堂 / 活动 / 展会试用意向
- [ ] 竞品或替代路径（投屏、微信传图、每人各开一路）开始抢场景
- [ ] 需要对外讲「降低人均成本 / 共享席位」的商业故事

未满足前：**不拆基础设施、不写大 PRD、不做完整权限/计费体系。**

---

## 3. MVP 范围（信号出现后做）

目标验证：**会不会有人真的开房，会不会有人真的加进来。**

| 能力 | 说明 |
|------|------|
| 主持人开共享 | 登录用户在进行中的转录会话上「开启共享」→ 链接 / 二维码 |
| 观众只读 | 打开链接即可看实时字幕（原文 / 译文 / 双语），大字、少操作 |
| 匿名加入 | 分享链接可匿名进入；默认只读 |
| 关房即断 | 主机停录或关共享 → 观众端结束 |
| 计费 | 仍只记主机那一路 realtime + 翻译；观众不计第二路 ASR |

### 建议实现顺序

1. [ ] 房间模型 + 只读 WebSocket fan-out（主机上行，观众只订阅 transcript/translation）
2. [ ] 分享链接 / 二维码
3. [ ] 匿名只读权限（无导出全文、无 AI、无音频默认）
4. [ ] 晚加入 catch-up（最近 N 条或关键帧）
5. [ ] 计费/席位展示文案（可选轻量「观众席」说明，非完整席位套餐）

### 与现有能力的复用

- 实时双语/译文阅读模式 → 观众端
- 长会话增量渲染 → 晚加入追进度
- 云端 session + 现有 WS 模式 → 会话级 pub/sub 扩展
- 手机响应式 UI → 扫码进房入口

## 5. 安全与产品边界（立项时必带）

- 默认只读；可选密码 / 过期时间 / 人数上限
- 主持人可踢人、一键关房
- 匿名观众默认：无历史导出、无 AI、无音频流
- 隐私：云端会话 + 匿名链接必须有关房与过期，避免会话内容意外外泄

---

## 6. 售前探针（未立项前可做）

访谈/试用时问一句：

> 如果一个人开转录、其他人手机扫码只看字幕，你愿不愿意用？什么场合？

收集「愿意 / 场合 / 是否接受匿名只读」即可，不承诺上线时间。

---

## 7. 相关讨论摘要

- 产品形态: **共享字幕房**，不是 Zoom 式双向协作
- 优先级: 主路径继续打磨个人实时转录 + 翻译 + AI 工作区；本能力挂 P1
- 半刚需策略: 产品叙事占一席，研发节奏二线；最小形态验证场景，不赌完整协作系统
